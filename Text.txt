For the system you're describing, I would implement it like this:

# 1. Published Chapters Not Showing

Current problem:

```text
Author
  ↓
Publish Chapter
  ↓
Chapter Saved
  ↓
Reader Cannot See It
```

The issue is usually that the reader page is not filtering correctly or the chapter status is not updating.

Your chapter system should have:

```text
Chapter
├── Draft
├── Published
├── CreatedDate
├── PublishedDate
└── Visibility
```

Reader pages should only fetch:

```text
Published = True
```

Library, Featured, Explore, and Book Detail pages should all pull from the same published chapter source.

Flow:

```text
Save
  ↓
Draft

Publish
  ↓
Published

Published
  ↓
Visible Everywhere
```

---

# 2. Flames System

I agree with limiting Flames.

WebNovel-style systems work because support is scarce.

I would use:

```text
3 Flames Per Day
```

For every user.

System:

```text
User
├── Daily Flames Available = 3
├── Last Reset Date
└── Flames Given Today
```

Flow:

```text
User receives
3 Flames

Give 1
Remaining = 2

Give 1
Remaining = 1

Give 1
Remaining = 0
```

Then:

```text
00:00 Server Time
```

or

```text
Local Midnight
```

resets:

```text
Remaining Flames = 3
```

---

# 3. Flame Restrictions

Prevent abuse.

Rules:

```text
Cannot flame own book

Cannot flame same book
multiple times in one day

Cannot exceed 3 flames daily
```

---

Example:


Ranking Score:

```text
Views
+
Favorites
+
Followers
+
Flames
```

Flames should have the highest weight.

# 5. Views System

I would strongly advise against:

```text
5 Minutes
=
10 Views
```

because this can be abused.

Someone could leave the chapter open for hours.

# Better View System

Track:

```text
Unique Reader
+
Minimum Reading Time
```

Example:

```text
User opens chapter

Reads 5 minutes

Award:
+1 View
```

Not:

```text
+10 Views
```

```text

       ↓

       ↓

       ↓

```

This prevents fake views.

---

# If You Want Bigger Numbers

Instead of:

```text
1 Reader
=
10 Views
```

use:

```text
1 Reader
=
1 View
```

and separately track:

```text
Engagement Score
```

Example:

```text
Read 5 Minutes
+10 Engagement

Read Entire Chapter
+25 Engagement

Comment
+15 Engagement

Flame
+100 Engagement
```

Then rankings use:

```text
Views
Favorites
Followers
Flames
Engagement
```

which is much harder to manipulate and gives a more accurate ranking system.

So my recommendation would be:

* Fix publishing so published chapters instantly appear everywhere.
* Give every user **3 Flames daily**, resetting at midnight.
* Make Flames the strongest ranking factor.
* Count **1 genuine read = 1 view**.
* Use reading time and completion rate as separate engagement metrics rather than inflating view counts.


Those are all features I would consider essential for Mynovel rather than optional enhancements.

# Paragraph Comments

This is one of WebNovel's strongest features.

When readers highlight or tap a paragraph:

```text
Paragraph
```

A comment button appears.

Example:

```text
Chapter Content

Paragraph 1

Paragraph 2
      ↑
Reader taps here
```

Opens:

```text
Comment on Paragraph
```

Benefits:

* Readers react to specific scenes
* Readers discuss dialogue
* Readers discuss plot twists
* Higher engagement

Structure:

```text
Chapter
├── Paragraph 1
│   └── Comments
│
├── Paragraph 2
│   └── Comments
│
└── Paragraph 3
    └── Comments
```

---

# Reader Interaction System

Readers should be able to:

```text
Like Paragraph
Comment Paragraph
Reply
Like Reply
Report Comment
```
